# DyTok — Symbolic Dynamic Tokenizer

Нейросимволический динамический токенизатор с continual-«сном»: дискретные слоты-коды
(комбинации VQ-идентификаторов), NMS-отбор пиков, sparse-гейты и фаза консолидации
между задачами (латентные «сны» + двухконтурная дистилляция + калибровка).

## Архитектура

```
сырые патчи (байты + признаки)
   │
   ├─ Layer 1 (обучаемый): byte_embed + patch_proj + 2D свёртка контекста
   │     └─ VQ-квантизация (EMA-кодбук, anchor-строки заморожены) → id-пиков (NMS)
   ├─ Слои 2-3 (обучаемые): slot_weights — обучаемые веса над алфавитом id-комбинаций
   │     └─ sparse ID-гейты (sparsify_slots каждый шаг)
   └─ MultiTokenizer: по одной «строке» на модальность → cross-attention фузия
         → фиксированная длина (наученные queries) → GRU-классификатор
```

Ключевые механизмы (подробнее — в `model.md` и `model.py`):

- **VQ-кодбук с EMA** и «anchors»: часть кодов замораживается (защита от катастрофического
  забвения на уровне признаков), reserve-коды пополняются из свежих данных.
- **Слоты = комбинации ID**: не один код, а набор id-комбинаций на слот; гейты разрежаются.
- **Sleep-консолидация** (`sleep_phase_consolidation`):
  1. `daytime_allocate_orphans` — выделение орфанных слотов под новые паттерны;
  2. обучение отдельной `novel_gru`-головы на новых классах (с подавлением «отсутствующих»
     и усилением общих);
  3. дистилляция основного `core_gru` по двум контурам: латентные «сны» (реплей из
     снапшота привычек) и реальные данные — с margin-подавлением новых классов в сновом
     контуре;
  4. калибровка логитов новых классов (`calib_beta`).
- **Протокол**: конец фазы → `freeze_anchors` + `snapshot_anchor_habits`;
  начало следующей → `daytime_allocate_orphans` → `expand_classifier` → `sleep`.

## Запуск

Требуется Python 3.10+, `pip install -r requirements.txt` (CPU-версия torch подходит).

### Continual learning на CIFAR (стандартный протокол)

```bat
:: быстрый смоук (CIFAR-10, 1 эпоха, 4k сэмплов)
venv\Scripts\python train_cl.py --dataset cifar10 --quick --tag smoke

:: основной эксперимент: 5 шагов × 20 классов, 5 эпох, со sleep (CPU, ~4 мин)
venv\Scripts\python train_cl.py --dataset cifar100 --epochs 5 --lr 1e-3 --tag sleep-5ep

:: абляция: то же, но без sleep (просто fine-tune)
venv\Scripts\python train_cl.py --dataset cifar100 --epochs 5 --lr 1e-3 --no-sleep --tag nosleep-5ep
```

Датасеты скачиваются автоматически в `data/` (torchvision). Результаты — в
`results/<dataset>_<tag>.json` + построчный JSON-лог на каждом шаге.

### Food-101 (шаблон, нужен локальный датасет + GPU)

```bat
venv\Scripts\python test.py
```

Ожидает `dataset/images/{split}/{category}/` и `dataset/texts/{split}_titles.csv`
(см. `LocalFoodDataset` в `test.py`).

## Протокол и метрики

Class-incremental: CIFAR-100 → 5 задач по 20 классов. В конце каждой задачи оценивается
точность **по всем виденным классам** (матрица A[t][i]). Итоговые метрики (task-level):

| Метрика | Формула | Что показывает |
|---|---|---|
| **AA** (Average Accuracy) | `mean_t mean_{i≤t} A_t(i)` | общая «память + обучение» |
| **BWT** (Backward Transfer) | `mean_{i<T} (A_T(i) − A_i(i))` | польза/вред новых задач старым |
| **Forgetting** | `max(0, mean_i (max_{t≥i} A_t(i) − A_T(i)))` | сколько старое забыто к финалу |

Диагностика (в JSON-логе): использование кодбука (`codes_used`), замороженные коды/слоты,
ID-стабильность токенов на фиксированном probe-батче между шагами.

## Результаты

CIFAR-100, 5 шагов × 20 классов, 0.14M параметров, CPU, seed 0. Шансовый уровень
(случайные угадывания) = 1% на 100 классов. Основной бег — 5 эпох, lr=1e-3 (~4 мин на CPU).

| Эксперимент | Final Acc | AA | BWT | Forgetting |
|---|---|---|---|---|
| **CIFAR-100, 5 эпох, sleep** | **0.0532** | 0.0975 | **-0.2226** | **0.1781** |
| CIFAR-100, 5 эпох, no-sleep | 0.0520 | 0.1018 | -0.2324 | 0.1859 |
| CIFAR-100, 2 эпохи, sleep (недообучен) | 0.0294 | 0.0545 | -0.1350 | 0.1080 |
| CIFAR-100, 2 эпохи, no-sleep (недообучен) | 0.0339 | 0.0549 | -0.1351 | 0.1081 |
| Диагностика: 10 эпох, все 100 классов сразу (одна задача) | 0.1193 | — | — | — |

Полные матрицы A[t][i] и диагностика (codes_used, frozen, id_stability, calib_beta,
время сна) — в `results/*.json`.

### Что показывают цифры

**Плюсы (работает):**

- Конвейер сквозной и воспроизводимый: VQ-токенизатор → слоты-комбинации → фузия →
  GRU, continual-режим с `expand_classifier` + sleep. Точность шага 1 — 18.8%
  (шансовый уровень 5%).
- Заморозка кодбука работает механически: со 2-го шага `frozen_codes` 255→256,
  `frozen_slots` 16/16 — признаки старых задач на уровне VQ защищены.
- Sleep дешёвый: ~6 с на шаг на CPU (160 шагов консолидации).
- Калибровка (`calib_beta` 0.15 → 2.71 по шагам) и отдельная novel-голова обучаются.

**Минусы (честно):**

- **Эффект sleep на этом масштабе минимален**: ΔBWT ≈ +0.01, ΔForgetting ≈ -0.008,
  ΔAA ≈ -0.004 — на уровне шума для одного сида. Польза консолидации не проявляется
  при 0.14M параметров и 5 эпохах; для её видимости нужен крупнее модель, больше задач
  или более сильное представление.
- **Дрейф токенов не останавливается заморозкой**: id_stability на фиксированном
  probe-батче падает 0.19 → 0.07 (со sleep) и до 0.05 (без). Замораживается кодбук,
  но не slot-гейты и slot_weights.
- **Чувствительность к числу эпох**: 2 эпохи → шансовый уровень (final acc 3%),
  5 эпох → 5.3%. На этом бюджете доминирует недообученность.
- **Представление — узкое место**: 8-мерная статистика патчей (mean/std/gx/gy по
  8×8) несёт мало информации; даже single-task-диагностика даёт 11.9% на 100 классов
  после 10 эпох.
- Один сид — нет доверительных интервалов; разница sleep/no-sleep может быть реальна,
  но нерешаема на этом бюджете.

## Ограничения и честные минусы

- Эксперименты на CPU: небольшое число эпох, результаты ниже, чем на GPU с полноценной
  дообученностью; CNN-базлайна (сравнимый по вычислительному бюджету) пока нет.
- Гиперпараметры чувствительны: вес commit-потери, спарсификации, `calib_beta` — эвристики.
- Food-101-прогон (`test.py`) требует GPU.
