## 1. H-Net — Dynamic Chunking for End-to-End Hierarchical Sequence Modeling
**arXiv 2507.07955v2** · Sukjun Hwang (CMU), Brandon Wang (Cartesia), Albert Gu (CMU/Cartesia)

**Проблема.** BPE-токенизация — рукотворный preprocessing, ломающий end-to-end дух LM: плохое char-level понимание, деградация на сложных языках/модальностях. Цель: обучить content-/context-зависимую сегментацию совместно с моделью, без эвристик.

**Метод.**
- **H-Net**: иерархическая U-Net-подобная сеть из S стадий. Каждая стадия: encoder (мелкая гранулярность, байты) → **Dynamic Chunking (DC)** слой → main network (крупная гранулярность) → **Dechunking** слой → decoder (восстановление до байтов). Main network — Transformer или Mamba-2; сам main network может быть H-Net (рекурсия = уровни абстракции).
- **DC-слой**: (a) **routing module** — предсказывает вероятности границ чанков p_t; ключевая идея — **косинусное сходство соседних представлений** (сравниваетadjacent vectors, а не изолированные предсказания); (b) **downsampler** — селективно сохраняет векторы только на позициях границ (сжатие L0→L1, target-соотношение, например N0=N1=3 → ~9x за стадию). STE для бэпропа через дискретный выбор.
- **Dechunking-слой**: (c) **smoothing module** — обучаемая интерполяция, превращает дискретные чанки обратно в непрерывные представления (критичен для стабильности); (d) **upsampler** — восстанавливает исходное разрешение по boundary indicators.
- Модель сама сжимается до целевого соотношения; выученные чанки ~4.5–5 байт/чанк (как BPE), границы — на whitespace/subwords/смысловых единицах, без какого-либо надзора.

**Результаты** (760M / 1.3B, compute- и data-matched vs BPE Transformer, FineWeb-Edu, до ~144B байт):
- 1-stage byte H-Net ≈ BPE Transformer по perplexity и downstream (7 задач). **2-stage: +2.2%/+2.6% среднего**, Large-2stage ≈ XL-Transformer (2x размер).
- Robustness: byte-level модели сильно устойчивее к текстовым пертурбациям (AntSpeak/Drop/RandomCase/Repeat/UpperCase HellaSwag); H-Net 2-stage — лучший и Robustness Score.
- Китайский (нет whitespace-cues): XWinograd-zh 59.9→66.3 vs Transformer; код — существенно лучше BPE; **DNA (HG38): 3.6× data efficiency** vs isotropic.
- Ablations: без smoothing — колебания compression ratio и деградация (наиболее критичный компонент); cosine routing и STE важны для стабильности и интерпретируемости границ. Mamba-2 в encoder/decoder критична: чистый Transformer (T2-T2) хуже всех даже на BPE-входе (SSM лучше сжимает в фиксированное состояние).
- Ограничения: масштаб ~1B (суперiores U-Net над token-only emerge на >1e21 FLOP), STE — эвристический компонент.

## 2. RL-токенизация — You Can Learn Tokenization End-to-End with Reinforcement Learning
**ICML 2026 (PMLR 306)** · Sam Dauncey, Roger Wattenhofer (ETH Zürich) · код: github.com/SamD770/bitter-lesson-tokenization

**Проблема.** Границы токенов — дискретное решение. Предыдущие end-to-end методы: эвристики (whitespace, entropy spikes) или **STE** (straight-through estimators — трактуют дискретное как непрерывное, без теоретических гарантий). Показано, что границы можно учить через **score function estimator (REINFORCE)** с RL-техниками снижения дисперсии.

**Метод.**
- **Autoregressive U-Net** (Nawrot 2022): byte encoder → стохастическое предсказание границ a ~ πθ(X, x) → downsample (выбор позиций с a=1) → mid-трансформер (full attention) → upsample (distribute-then-add) → byte decoder. Всё авторегрессивно (causal).
- **Score function**: ∇θ E_{a~πθ}[log pθ(y|a,x)] = обычный CE + REINFORCE-градиент по границам (вывод в App. A.1). Прямая оптимизация дискретной задачи → более жёсткие теоретические гарантии, чем у STE, но выше дисперсия.
- **Снижение дисперсии (ключевой вклад)**: time discounting и control variate на основе early-exit модели (предсказания «раннего выхода» Gi, положительный сигнал); без них дисперсия непригодна на практике.
- Boundary function: логиты границ со sliding window w по соседним байтам (w=1 в абляции достаточно).
- **Target downsample rate**: L_target = l̄ · detach(p̄ − p̄_target) — мягкий штраф за отклонение среднего соотножения от цели.
- Полный loss: L_auto + λπLπ + λtarget L_target + λearly L_early (λπ=λtarget=1e-2, λearly=0.1).

**Эксперименты** (147M, FineWeb, последовательности 4096 байт, target rate 15; гиперпараметры из scaling laws):
- Без индуктивного bias границы ложатся на whitespace, "\n", " ", точки (n=2 слоя: ровно ~2 байта/токен + точки; n=4,6 — whitespace + чанкирование длинных слов).
- Validation loss стабильно лучше STE (Nawrot, H-Net) и uniform baseline; **bits-per-byte (ниже лучше): Ours w=1: PIQA 1.561, HellaSwag 1.199, ARC-e 1.987, LAMBADA 1.584, FineWeb test 1.280** — лучшая среди 4 основных методов.
- **BPE guidance** (BPE 200k vocab на FineWeb, rate 0.207): 1.299 vs our learned 1.297 — практически идентично, без внешних prior'ов. Единственная динамическая стратегия, достигающая уровня BPE.
- Python (CodeParrot, 90M): границы в начале имён модулей, пробел ≥2 байта, «пропуск» Apache-лицензии; bpB 0.568 vs 0.769 у H-Net (STE).
- Ограничения: 147M — downstream-эффекты выученной токенизации видны только на >1e21 FLOP; открытый вопрос — как optimal aspect ratio масштабируется с размером модели; variable target rate обучился «робустнее, но менее эффективно».

## 3. DiCode — Dreaming in Code for Curriculum Learning in Open-Ended Worlds
**ICML 2026 (PMLR 306), arXiv 2602.08194v2** · Mitsides, Faldor, Cully (Imperial College) · проект: konstantinosmitsides.github.io/dreaming-in-code

**Проблема.** Open-ended learning: агенты быстро выходят на плато. UED поддерживает «Goldilocks»-сложность, но классические UED работают в низкоразмерных параметрических пространствах. FM-генерация программных сред (Faldor 2025) даёт новизну, но не **курсус** — последовательность сред, строящуюся на предыдущих навыках.

**Метод.**
- **DiCode**: FM (open-weights **Qwen3-235B**) «мечтает» новые среды, синтезируя **исполняемый код** уровня (описание + Python), **условно** на parent-уровень (выбор из archive по learnability) и **профиль текущей компетентности агента**.
- Код исполняет **fixed world engine** (игровой движок Craftax; в общем случае — game/physics engine): гарантирует физическую валидность, без world model, без галлюцинированных динамики. «Мечтание» здесь = построение курса, а не sample efficiency.
- **Цикл генерации**: parent selection (learnability-based) → FM генерирует новый уровень → compile check → Training Batch (целевая среда + новые уровни + архивные уровни через **PLR** — Prioritized Level Replay, Jiang 2021) → RL-обучение → обновление archive. Асинхронная генерация (RL идёт параллельно FM-инференсу).
- Формализация: **UPOMDP** (Dennis 2020). Бенчмарк: **Craftax** (Minecraft-подобный, JAX, процедурный бесконечный мир, tech tree: survival→crafting→combat→десценд). Агент: **PPO + Gated Transformer-XL** (SOTA-solver). Базлайны: PLR, SFL, DR, PPO-GTrXL. Бюджет 2e9 steps, 8 seeds, held-out 1024 инстансов.

**Результаты.**
- Final mean return **48.55 vs 41.59** у лучшего базлайна (**+17%**), статзначимое лидерство на всём протяжении.
- Instrumental milestones: **Make Iron Armour 47% vs 15%**; Gnomish Mines (floor 2) — 32% эпизодов vs 9%.
- Late-game combat, где все базлайны **0%**: **Defeat Gnome Warrior 15%, Gnome Archer 11%**; Make Diamond Sword 6% vs 3%.
- Квали: семантическая прогрессия курса (щедрый старт → слой combat → deep exploration); FM ведёт себя как **учитель** — при высокой компетентности агента **снимает resource scaffolding** (diff-модификации уровня 112→143: REMOVE coal/iron/pre-built workstation, ADD mob pressure/expanded objective); средний success на training-уровнях стабилен **~0.5** (zone of proximal development).
- **Абляции**: Random Parent 46.44 (но late-game combat коллапсирует к ~0% — parent selection критичен для глубоких целей); **Goal Only 42.82** (reshaping/scaffolding — главный драйвер, goal-селекция сама по себе почти бесполезна); FM capability 235B→80B→30B: 48.55→45.88→44.38 (качество курса масштабируется с reasoning-силой FM); **Open-Loop 41.12 ≈ baseline** (без closed-loop grounding на perf-агента генерация не работает).
- Ограничения: fixed engine ограничивает «изобретение» — FM настраивает мир, но не изобретает новые законы физики; перенос в домен требует domain-specific toolkit (App. B: knowledge base (immutable rules) + mutable API для FM).

## 4. TIDE — Every Layer Knows the Token (Token Identity Delivered Everywhere)
**arXiv 2605.06216v1 [cs.CL]** · A. Jaiswal, L. Hannah, H.-B. Kim, D. Hoang, M. Farajtabar, M. Cho (Apple), май 2026

**Проблема.** «Single-injection assumption»: индекс токена ищется ровно один раз на входном embedding-слое и навсегда выбрасывается. Два структурных сбоя:
- **Rare Token Problem**: по закону Ципфа кумулятивный квадратичный градиент эмбеддинга e_v пропорционален частоте f_v (E[Σ‖∇e_v‖²] ≤ τ·f_v·B·T·G²): на 200B токенов hapax-токены получают ~1 660 ненулевых обновлений, частые — ~1.66×10⁹ (разрыв 10⁶). Эмпирика на LLaMA-Base-1B: L2-нормы редких эмбеддингов *уменьшаются* по ходу обучения (0.958 у редких против 1.555 у частых).
- **Contextual Collapse**: два семантически разных токена в почти одинаковом синтаксическом контексте → неразличимые скрытые состояния во всех слоях. Нижняя граница (Prop. 2.2): если ‖h_u−h_v‖<δ, то для любого FFN с Lipschitz-константой L_FFN max-ошибка ≥ (C−L_FFN·δ)/2 — коллапсировавшую пару нельзя развести ни при какой ширине FFN. У позиции есть механизм восстановления (RoPE ре-инжектится в каждом attention-слое); у токен-индекса — нет.

**Метод.** Параллельный «памятный» контур поверх стандартного LLaMA-style трансформера:
- **EmbeddingMemory**: ансамбль из K независимых MemoryBlocks; блок = собственная таблица E_k ∈ R^{|V|×d_b} + RMSNorm (без шаринга между блоками → каждый учит собственную проекцию пространства токен-идентичности).
- **Depth-conditioned softmax-роутер**: линейная комбинация K блоков + обучаемый **NULL bank**, условием служит *post-attention* скрытое состояние данного слоя; результат **аддитивно** добавляется в residual stream. Тензор памяти вычисляется один раз на forward-pass и инжектится в **каждый** слой.
- Теорема: TIDE (i) асимптотически обобщает стандартный трансформер, (ii) усиливает кумулятивный градиентный сигнал на токен в K раз, (iii) обходит Lipschitz-ограничение FFN, давая дискретный токен-индексированный вход, независимый от hidden states.

**Эксперименты.** LLaMA-style 750M / 1B / 3B, DCLM 200–500B токенов, LLaMA-3 tokenizer (128K vocab), K∈{2,4,8,16,24}:
- LAMBADA PPL (1B): 5.19 (base) → 4.89 (K=8) → **4.60 (K=24)**; среднее по 8 бенчмаркам: 61.4 → **63.7**. На 3B: 4.00→3.86 PPL, 67.2→68.3 среднее.
- Рост с K **монотонен без насыщения** (2→24); уже при 100B токенов TIDE с K=2–4 блоками достигает PPL, который базовая модель выдаёт только к 200B токенов (быстрее эффективная конвергенция).
- Эффект редкостно-смещён: CE редчайшего бина −0.421 nats (K=0→24) против −0.075 у частых (5.6× по абсолютному выигрышу); роутер «открывает дверь» памяти для редких: α_NULL = 0.53 (редчайший дециль) → 0.89 (частый) — доля массы памяти для редчайших ≈47%.
- Таблицы сжимаемы: 10–30% среза почти без потерь, агрессивное сжатие → взрыв PPL (до +587% на WikiText-2).
- Ablation: нуление memory-path на любом одном слое деградирует PPL — идентичность нужна на всех глубинах.

**Ограничения.** Масштаб до 3B; память добавляет параметры (TIDE-24E-1B — больше 1B); роутер линейный; взаимодействие с прочими видами sparsity/MoE не изучено.

## 5. L³ — Large Lookup Layers
**arXiv 2601.21461v3, ICML 2026** · A. Tseng, C. De Sa (Stanford)

**Идея.** Обобщить embedding-таблицу токенизатора на decoder-слои: слой L³ = банк key/value эмбеддингов на каждый токен, **статически** маршрутизируемый по токен-ID (без обучаемого роутера) с **context-dependent** агрегацией — hidden state «внимает» по банку своего токена. Новая ось sparse scaling, ортогональная MoE.

**Метод.**
- L3(x, t) = W_mix [LayerNorm(W_up(V_tᵀ · Softmax(K_t·x))); x], где K_t ∈ R^{d_t×d_in} (ключи), V_t ∈ R^{d_t×d_emb} (значения): d_t — число эмбеддингов у токена t.
- **Embedding Allocation** — главный гиперпараметр v = Σ_t d_t (дефолт 710K): вариант **алгоритма LZW** (двойственная задача к lossless-сжатию): скан корпуса, кэширование суффиксов, частым токенам — больше эмбеддингов («then» — 512, редкий «orm» — 1), потолок k=512. Ablation: uncapped LZW — лучший PPL, но кривой доступ (топ-токен >20K из 710K); uniform — заметно хуже.
- **Hardware**: L³ делает только channel mixing → сортировка батча по token ID даёт block-diagonal mask (ядра MegaBlocks/FlexAttention); требуемые (K_t, V_t) известны заранее (статический роутинг) → **CPU offload + prefetch** во время pre-L³ compute. У MoE offload невозможен: эксперты узнаются только в роутере, sparsity 4–32× против 1000×+ у L³.

**Эксперименты.** Llama-based, L³ вставлен *между* decoder-слоями (не заменяя MLP), 800M / 1.5B / 2.6B active params, FineWeb-Edu 10/20/30B токенов, ctx 2048, BPE 180K (4.7 байт/токен), 1–3 слоя L³ на модель (sparsity 2–4×, v=710K, k=512):
- Val PPL: 800M: 22.02 → 20.23 (2 L³) → 19.59 (3 L³, всего 5.2B params); 1.5B: 18.83 → 16.72 (4.6B); 2.6B: 15.43 → **14.51** (7B всего).
- 0-shot (2.6B + 2 L³): ARC-C 36.4→38.2, ARC-E 68.9→71.2, HellaSwag 44.2→45.0, PIQA 71.2→71.7, WinoGrande 57.3→58.8; среднее 55.6→57.0.
- Побеждает iso-FLOP dense и iso-sparse MoE; выигрыш стабилен с начала обучения (без warmup дискретного роутера, как в MoE); scaling: линейный рост sparsity слоями L³ ≈ линейный рост параметров эквивалентной dense-модели (power-law fit).
- Заключение: «новая, более эффективная ось sparse scaling»; комбинация MoE+L³ в одной модели оставлена на будущее.

**Ограничения.** BPE-вход (статическая токенизация), масштаб до 2.6B active, аллокация **статична на корпус** — адаптации к дрейфу распределения нет (критично для continual learning).

## 6. Per-Layer Embeddings в Gemma 3n/4 (PLE) — model cards, не статья
- **Gemma 3n** (2025): 30 per-layer embedding-таблиц, применяются к **аудио**-токенам (в HF-реализации — `PerLayerEmbedder`); текст продолжает использовать обычный входной embedding.
- **Gemma 4 E2B/E4B** (2026): per-layer таблицы на весь vocabulary; «effective» параметры: E2B — 2.3B effective / 5.1B с эмбеддингами, E4B — 4.5B / 8B.
- Механика (анализ S. Raschka): token ID → per-layer lookup + token embedding проецируется в «packed PLE»-пространство; hidden state каждого блока **гейтит** PLE-срез своего слоя, проецируется обратно, нормализуется и добавляется как дополнительный residual.
- Источники: model cards Gemma 3n/4, HF-реализация (PerLayerEmbedder), галерея S. Raschka по per-layer embeddings.

## 7. Qwen3.8-Flash-Next — N-gram Embedding Layer
**arXiv 2608.30320v1 [cs.CL]** · Qwen Team, 31 августа 2026 · technical report (архитектура + абляции)

**Модель.** Sparse MoE: 125B параметров всего, 6B активированных на токен, плюс **51B параметров n-gram embedding tables, которые держат вне accelerator'а** (host memory). Предшественник — флагман 397B-A17B (Qwen3.7-Plus). На 14 pre-training-бенчмарках (MMLU, MMLU-Pro, MMLU-Redux, BBH, SuperGPQA, GPQA, GSM8K, MATH, EvalPlus, MultiPL-E, SWEBench-Pretrain, MGSM, MMMLU, INCLUDE) лидирует на 8, отстаёт на 6 — не более чем на 2.6 пункта — при ~1/3 активных параметров, ~1/3 тренировочных токенов и ~1/9 тренировочных FLOPs.

**Прочие компоненты (контекст).**
- Token mixing: layer-wise hybrid **Gated DeltaNet** (GDN) + глобальное внимание (1 full-attention слой на каждые 4); на continued-pretraining full-attention заменяется на **QSA** (Qwen Sparse Attention: скоринг контекста в микро-блоках через компрессованный лёгкий индексер — стоимость индексирования падает с длиной).
- **Gated Residual (GR)**: residual stream расширяется до 4 ветвей, чтение через elementwise-гейт — ёмкость + рескейлинг, стабилизирующий обучение (p99 нормы градиентов в 4.2× ниже, без qk-clip/SwiGLU-clip).
- Оптимизатор **Muon** (Newton–Schulz, 8 итераций, коэффициенты Polar Express): вместе с GR сдвигает оптимальный LR и batch size вверх, делает batch-size warmup ненужным; в production-ране GR даёт −0.026 loss, полный рецепт ещё −0.032 при 276B токенов.
- MTP-модули (×3, переиспользуют QSA-индексы в speculative decoding), ядра FlashQLA (2–3× forward, ~2× backward против Triton).

**N-gram Embedding Layer (§2.3) — ядро интереса.**
- Идея: обобщение unigram lookup — **короткие n-граммы, заканчивающиеся на каждом токене, служат ключами в embedding tables**; извлечённые векторы аугментируют представление токена. Поиск по памяти кондиционируется на *локальный контекст*, а не только на токен-идентичность — «статически context-dependent» ключ в противовес динамическому роутингу L³.
- Механика: **multi-head hashing** n-грамм в слоты таблиц (без явного раздувания словаря), инжект в residual stream через **contextual gating**; масштабное правило — 300 токенов на активный параметр (TPP).
- **Детерминированный addressing** → таблицы живут в host memory, **асинхронный prefetch** перекрывается с forward-вычислениями (в конфиге Qwen ~51B параметров ≈ 40% всей ёмкости — вне accelerator'а, при пренебрежимом росте FLOPs/латентности на токен).
- Размещение (Tab. 7): один слой на глубинах 1–25: loss 1.585 (без n-gram) → 1.540–1.544; downstream-среднее 45.44 → 47.30–47.94 (лучше всего 2-й слой). Мульти-слойные конфигурации (2+15, 2+25) — без последовательного выигрыша: **одного слоя достаточно**; ставят в слой 2, чтобы prefetch перекрывался с вычислениями первого слоя.
- Скейлинг словаря (V = 250K базового токенизатора):
  - При фиксированном *общем* бюджете параметров (Tab. 8; MoE-эксперты урезаются): loss не монотонен, минимум при **10× (25%)**: 1.202 → 1.197; downstream-выигрыш неочевиден → n-gram и MoE играют *разные* роли в скейлинге ёмкости.
  - При фиксированном MoE-бюджете (Tab. 9): 20× → 200×: loss убывает монотонно 1.585 → 1.526, но downstream насыщается (MMLU 62.78 → 64.85, пик к 50×); **китайские бенчмарки (C-Eval, CMMLU) растут последовательно** со размером словаря (66.9→74.9 / 68.1→73.2).
- **Негативный результат (важен):** token normalization для сжатия словаря, неравномерная аллокация по n-gram-порядкам, частотное разбиение слотов — **без последовательного выигрыша** в рецепте Qwen. (Контраст с L³, где LZW-аллокация работала на уровне transformer-слоя: перенос не автоматический.)
- Оптимизация: сами таблицы — Adam без weight decay; key/value-проекции — Muon.

**Значение для нашей темы.** N-gram-слой — индустриальный шаг от «таблицы, индексированные по токен-ID» (TIDE/L³/PLE) к *context-dependent lookup*: ключ — не токен, а **окно фиксированного локального контекста** (хешированное). Динамическая токенизация (H-Net/Dauncey) обобщает ту же идею дальше: ключ = *выученная* граница сегмента произвольной длины. Рецепт Qwen (детерминированный addressing → offload + prefetch, TPP-правило, contextual gating, один слой на малой глубине) — готовый инженерный шаблон для иерархической версии.

## Связь с нашей темой (динамическая токенизация для непрерывного обучения языковых агентов в воплощённых средах)

1. **П1 (H-Net)** — референсная архитектура «токенизатора внутри модели»: routing (косинусные границы) + smoothing + STE + target ratio. Даёт: end-to-end сегментацию, robustness к пертурбациям, интерпретируемые границы.
2. **П2 (Dauncey)** — альтернатива STE: REINFORCE по границам с RL-variance-reduction; BPE восстанавливается из данных только; компактный маленький масштаб (147M) для бытовых экспериментов; чистые теоретические гарантии.
3. **П3 (DiCode)** — воплощённая/continual-сторона: LLM как «учитель» генерирует исполняемые среды-курсы, closed-loop по perf-профилю агента; UED в программном представлении среды.
4. **П4 (TIDE)** — доказательство принципа «идентичность должна ре-инжектиться на всех глубинах»: K параллельных lookup-каналов = K× усиление градиента; null bank = выученный гейт памяти; эффект концентрируется на редких токенах. Для нашей темы: *идентичность* чанка в иерархии динамической токенизации — ровно то, что TIDE ре-инжектит; в иерархии эта идентичность *зависит от уровня*.
5. **П5 (L³)** — статический роутинг по token ID + context-dependent агрегация без обучаемого роутера; information-theoretic (LZW) аллокация lookup-бюджета по словарю; hardware-friendly sparse-ось (offload/prefetch). Для нашей темы: бюджет эмбеддингов должен распределяться *неравномерно* — по словарю (L³) или **по уровням иерархии** (своя ниша).
6. **П6 (Qwen3.8-Flash-Next)** — индустриальный n-gram embedding layer: ключ = фиксированный локальный контекст (хешированная n-грамма), а не токен-ID; детерминированный addressing → host-memory offload + async prefetch (51B параметров вне accelerator'а); одного слоя на малой глубине достаточно; при фиксированном MoE-бюджете loss убывает монотонно, но downstream насыщается (китайский растёт последовательно); неравномерная аллокация/частотное разбиение — **без выигрыша** в их рецепте (важный контраст с L³).
7. **Своя ниша (ключевой синтез).** TIDE, PLE (Gemma 3n/4) и L³ занимают пространство «эмбеддинги на каждый *трансформерный слой*, индексированные по токен-ID»; n-gram-слой Qwen делает шаг к *context-dependent ключам* (окно фиксированной длины). В иерархии динамической токенизации (П1–П2) естественный объект — **пер-левеловые embedding-пространства**, где ключ — не фиксированная n-грамма, а **выученный сегмент произвольной длины** (слово→фраза→навык); L3-style аллокация распределяется по *уровням*, а не по словарю, и в continual learning (П3) должна быть **адаптивной** (статический LZW L³ и статический хешированный n-gram Qwen — базлайны; closed loop DiCode — сигнал адаптации). Это прямой мост П1–2 → П3 и точка публичной новизны.
8. **Возможные точки синтеза**: (а) динамическая токенизация *опыта* — end-to-end chunking наблюдений/действий в embodied-средах (H-Net-стиль) для RL/языковых агентов; (б) курс через FM-генерацию сред (DiCode) + выученная сегментация траекторий как механизм «памяти/абстракции» уровня слов→фраз→навыков; (в) вопрос: оптимальный aspect ratio/целевое соотношение сжатия в зависимости от масштаба модели и горизонта среды (открытые проблемы П2 + tech tree П3); (г) пер-левеловые embedding-пространства + адаптивная аллокация (п. 7) — кандидат на первый эксперимент: H-Net 2-stage, где таблица второго уровня инжектится через TIDE/L³-style роутер или через Qwen-style детерминированный prefetch с host memory (offload иерархии), а не только через residual-smoothing; (д) воспроизвести негативный результат Qwen: переносится ли LZW-аллокация L³ на n-gram/иерархический уровень (их рецепт — «нет», L³ — «да» — граница эффекта стоит отдельного исследования).
